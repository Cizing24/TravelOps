# TravelOps 展示操作指南

使用 README 的本機 Compose 指令啟動合成環境。以
`docker compose exec -T app php artisan travelops:demo --reconciliation-fixture --no-ansi`
建立展示帳號及交易。指令只在本地專用展示資料庫執行，請將新生成的密碼保存在本機。

場館、票券與交易都是合成資料。付款、退款、供應商回應及 Email／LINE 投遞由本地 Mock 模擬。已有 Demo 時可直接使用既有帳號和仍有庫存的商品。

## 5–8 分鐘展示

| 時間 | 角色與操作 | 畫面及工程重點 |
| --- | --- | --- |
| 2 分鐘 | 旅客從 `/products` 買一張潮線水族館單館票。於訂單頁選擇模擬付款成功。 | 購票前確認效期、場館、可售量與預估金額。透過進度步驟從付款走到開券，再確認已用及剩餘權益。 |
| 2 分鐘 | 門市店員從 `/pos` 選灣岸展示門市，對同一商品賣一張現金票。 | 改變張數與付款方式，核對送出前摘要與落帳金額。若已收款且等待開券，從同筆交易查看結果。 |
| 1 分鐘 | 營運人員到 `/ops/inventory-movements` 查看剛才兩筆訂單的流水。 | 用同一商品的預留與出售紀錄解釋兩個通路共用庫存。 |
| 2 分鐘 | 旅客再買一張島岸工藝館單館票，選擇重複成功回呼。營運人員到 `/ops/outbox-events` 依訂單查詢。 | 對照旅客票券數量與供應商工作結果，說明重送與非同步開券。 |

## 技術深度展示

依序使用下列章節。多供應商履約比較同步及回呼開券，並用重複付款情境展示冪等性。接著用未核銷的票券展示退款處理中暫停核銷及確認後回補庫存。最後比較合成帳冊差異的人工處理，以及同一組篩選條件下的營運畫面與 CSV。需要對照實作時，可從 [工程案例](../portfolio/TRAVELOPS_CASE_STUDY.md) 找到程式與測試。

## 多供應商履約

1. 以 `customer@travelops.test` 登入。
2. 分別購買潮線水族館單館票及島岸工藝館單館票。
3. 選擇模擬付款成功或重複成功回呼。兩張訂單各自只產生所購數量的票券。
4. 以營運人員登入並開啟 `/ops/outbox-events`。以供應商或訂單查閱同步與非同步結果。

## 門市銷售與庫存

1. 以 `pos-a@travelops.test` 登入並選取灣岸展示門市。
2. 選擇有庫存的商品、張數及現金或模擬卡片。開券後從銷售明細開啟票券憑證。
3. 以 `pos-supervisor-a@travelops.test` 查看灣岸展示門市的日結。日結按臺灣營業日、付款方式和實際已付款訂單統計。
4. 以營運人員在 `/ops/inventory-movements` 查看同一商品的預留與出售紀錄。管理員可在商品頁輸入理由並調整庫存。
5. `pos-b@travelops.test` 可進入港城展示門市。以該帳號開啟灣岸門市的銷售明細會收到 HTTP 403。

## 非同步退款

1. 旅客購買票券並完成付款，保留未核銷狀態。
2. 從訂單詳情申請整筆退款。營運人員到 `/ops/refunds` 選擇核准及「延遲確認」。
3. 觀察待處理到已退款。等待期間票券詳情會提示暫停核銷，場館若收到原憑證也會看到暫停核銷訊息。
4. 退款確認後，旅客票券頁會顯示撤銷，庫存流水新增一筆退款回補。

## 交易對帳

1. 以營運人員開啟 `/ops/reconciliation` 並執行當日對帳。可選供應商或最多 31 天的營業日區間。
2. 展開差異的「訂單參照與追蹤編號」，找到參照尾碼 `000000000080`。比較內外部帳冊的狀態、金額或張數。
3. 輸入原因並標記已處理。再次執行同日對帳，原差異保留處理結果。

## 通知與報表

1. 旅客在 `/my/notifications` 啟用模擬 Email 和 LINE，再完成付款、開券或退款。
2. 開啟通知中心查看站內訊息並標記已讀。營運人員可在 `/ops/notification-deliveries` 查看模擬投遞。
3. 營運人員在 `/ops/reports` 選日期、通路、門市或供應商，套用篩選後匯出 CSV。畫面金額以新臺幣元顯示，CSV 以新臺幣分為單位。
4. 若啟用 LINE，距到期一天的提醒會模擬首次投遞失敗，供營運查看自動重試。
