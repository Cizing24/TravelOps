# ADR 002 · InnoDB 交易一致性

下單先鎖旅客列保護下單 key，然後鎖商品及可售庫存。商品模板與初始庫存透過同一筆管理交易寫入，修改模板時亦鎖商品。後續付款、到期、開券、核銷與退款皆先鎖訂單，再操作下游資料。核銷先取得操作人員列鎖核對場館授權，再鎖訂單、票券及指定權益。可復原的交易死結允許 Laravel 重試，持久化 unique keys 是最終防線。

回呼 HMAC 覆蓋原始 request body。系統鎖訂單、核對付款參考、幣別與金額，原子認領 webhook ID。重送相同內容回傳既有 outcome，同 ID 不同內容拒絕。當前時間到達截止即關閉付款，與庫存釋放共用訂單鎖。

退款以訂單為整筆單位。持有同一訂單鎖時查核銷、變更付款及退款狀態、回補庫存、撤銷票券與權益、停止未完成開券並寫稽核。任何一步失敗即回滾。資料庫狀態優先於 HTTP 回應。

首次核銷成功的時間以 UTC 儲存，效期為該時間加 N 個 24 小時日，到期瞬間即拒絕。臺灣時間只在 UI 轉換。若從未核銷，MVP 票券沒有預先到期日。

參考 [MySQL 8.4 InnoDB locking reads](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。
